# Security

## Reporting a Vulnerability

This is a private personal finance application. If you discover a security issue, please open a [GitHub Issue](https://github.com/mctelinde/budge-it/issues) or contact the repository owner directly. Do not include sensitive data (credentials, tokens, account numbers) in issue reports.

---

## Security Model

### Authentication

- All user authentication is handled by **Supabase Auth** (email + password).
- The app never stores passwords — Supabase manages credential hashing and session tokens.
- All authenticated routes in the app are protected by a `ProtectedRoute` wrapper that redirects unauthenticated users to `/auth`.

### Database Access & Row Level Security (RLS)

- The database is **PostgreSQL hosted on Supabase** with Row Level Security enforced on all tables (`transactions`, `budgets`, `plaid_items`, `plaid_accounts`, `accounts`, etc.).
- The client-side app uses the **anon key** only. RLS policies ensure every query is automatically scoped to the authenticated user — no user can read or modify another user's data, even with direct API access using the anon key.
- The **service role key** (which bypasses RLS) is only used inside Supabase Edge Functions on the server side and is never exposed to the browser or committed to the repository.

### Plaid Integration

- **Plaid access tokens are never sent to the browser.** The token exchange flow is:
  1. Browser opens Plaid Link and receives a one-time `public_token`.
  2. Browser sends `public_token` to the `plaid-exchange-token` Edge Function.
  3. Edge Function exchanges it for a permanent `access_token` server-side and stores it in `plaid_items` (Supabase, server-only).
  4. Only the Edge Function ever holds or uses the `access_token`.
- Plaid credentials (`PLAID_CLIENT_ID`, `PLAID_SECRET`) are stored as **Supabase project-level secrets** and injected at Edge Function runtime via `Deno.env.get()`. They are never in source code.

### Cron Authentication

- The daily transaction sync Edge Function (`plaid-sync-transactions`) accepts two auth modes:
  - **User JWT** — browser-initiated sync, scoped to the authenticated user.
  - **`x-cron-secret` header** — used by the Windows Task Scheduler PowerShell script to trigger an all-users sync. The secret is a random 48-character hex string stored in `.env.local` and as a Supabase project secret (`CRON_SECRET`). It is never committed.

### HTTPS

- The production server (PM2 + `serve`) and Vite dev server both enforce **HTTPS** using a locally trusted certificate generated by [mkcert](https://github.com/FiloSottile/mkcert).
- Certificates are stored in `certs/` which is **gitignored** and never committed.
- All traffic between the browser and local server is encrypted, including on LAN access.
- All traffic to Supabase and Plaid APIs uses HTTPS by default.

## Secrets Inventory

| Secret | Where stored | Committed? |
|--------|-------------|------------|
| `REACT_APP_SUPABASE_ANON_KEY` / `VITE_SUPABASE_ANON_KEY` | `.env.local` | ❌ Never |
| `SUPABASE_PAT` (Personal Access Token) | `.env.local` | ❌ Never |
| `CRON_SECRET` | `.env.local` + Supabase project secret | ❌ Never |
| `PLAID_CLIENT_ID` | Supabase project secret | ❌ Never |
| `PLAID_SECRET` | Supabase project secret | ❌ Never |
| Supabase service role key | Edge Function runtime only | ❌ Never |
| Plaid `access_token` | Supabase `plaid_items` table (RLS-protected) | ❌ Never |
| TLS cert + key | `certs/` (gitignored) | ❌ Never |

The Supabase anon key is safe to treat as semi-public — it cannot bypass RLS — but it is still kept out of the repository as a precaution.

## If a Secret Is Compromised

| Secret | Action |
|--------|--------|
| Supabase anon key | Rotate in Supabase Dashboard → Settings → API |
| Supabase PAT | Revoke at supabase.com/dashboard/account/tokens and generate a new one; update `.env.local` |
| `CRON_SECRET` | Generate a new random value, update `.env.local` and the Supabase project secret (`POST /v1/projects/{ref}/secrets`) |
| Plaid credentials | Rotate in the [Plaid Dashboard](https://dashboard.plaid.com/) and update the Supabase project secret |
| Plaid `access_token` (per institution) | Call Plaid `/item/remove`, delete the row from `plaid_items`, and reconnect via Plaid Link |
| TLS cert/key | Regenerate with `mkcert localhost 127.0.0.1 <LAN-IP>` inside the `certs/` directory |

## Dependencies

- **Supabase** manages auth, database, and Edge Function hosting. Review their [security practices](https://supabase.com/security).
- **Plaid** handles bank connectivity. Review their [security overview](https://plaid.com/documents/plaid-security-overview.pdf).
- Frontend dependencies are managed in `app-v2/package.json`. Run `npm audit` inside `app-v2/` to check for known vulnerabilities.
